# Stage 3 — FAT12 file search and loading

Source: [`boot/fat12.inc`](../boot/fat12.inc)

## Layout from the BPB

Every number comes from the BPB stage1 left at `0x7C00`:

```
root_lba  = reserved + num_fats * sectors_per_fat   = 64 + 2*9  = 82
root_secs = (root_entries * 32 + 511) / 512         = 224*32/512 = 14
data_lba  = root_lba + root_secs                    = 96
cluster N → data_lba + (N - 2) * sectors_per_cluster
```

Clusters 0 and 1 are reserved, which is why the data area starts at
cluster 2.

## Directory entries

The root directory is an array of 32-byte entries:

| Offset | Size | Field |
|--------|------|-------|
| 0 | 11 | name, 8.3, space padded: `KERNEL  ELF` |
| 11 | 1 | attributes (`0x08` volume label, `0x10` directory, `0x0F` long-name entry) |
| 26 | 2 | first cluster |
| 28 | 4 | file size in bytes |

A name byte of `0x00` ends the directory; `0xE5` marks a deleted entry.
`fat12_load_file` skips anything with bit 3 or 4 set (labels, directories
and long-name fragments) and compares the 11-byte name with `repe cmpsb`.

## Following the chain

FAT12 packs two 12-bit entries into three bytes:

```
bytes:   [ AB ] [ CD ] [ EF ]
entries:  cluster 2k   = 0xDAB
          cluster 2k+1 = 0xEFC
```

So for cluster `N`, read the 16-bit word at byte offset `N + N/2`; an even
`N` keeps the low 12 bits, an odd `N` the high 12 bits. Values `0xFF8` and
above end the chain.

## Loading past 64 KiB

The destination is `DX:0000`. After each sector the loader adds `0x20` to the
segment (`0x20 * 16 = 512`) and keeps the offset at 0, so a file can be any
size up to the space the caller allows. The caller passes that limit in
`[fat_max_size]`: the kernel buffer runs from `0x10000` to the FAT scratch
buffers at `0x60000`, so `KERNEL.ELF` may be at most 320 KiB. A larger file
is refused before a single byte is read.

Return values: `CF=0, EAX=size` on success; `CF=1, EAX=0` if the file is
missing; `CF=1, EAX=size` if it is too large.

## Building the image

The Makefile writes the image by hand instead of trusting `mformat`, so the
BPB on disk is exactly the one in `stage1.asm`:

1. 2880 zero sectors
2. stage1 into sector 0, stage2 into sectors 1+
3. `F0 FF FF` at the start of both FATs (media byte + end-of-chain marker
   for the two reserved clusters)
4. `mcopy` the kernel and every file in `rootfs/`
